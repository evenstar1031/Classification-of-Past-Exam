# 필기본 → 수업별 학습자료 (3부 구성)

사용자는 이 PDF 하나로 시험공부를 한다. 코딩은 하지 않으니 결과 위주로 짧게 한국어로 보고한다.

| 부 | 내용 | 출처 |
|---|---|---|
| 표지 | 과목 · 강 번호 · 수업명 · 목차 | 자동 |
| 1부 개념 설명 | 필기본의 **모든** 내용을 설명 | Claude가 `1_설명.md` 작성 |
| 2부 기출문제 | 그 수업으로 분류된 기출 전부, 최신 연도부터, `문제지/`와 같은 양식 → 끝에 **정답·해설 모음** | `분류/` + `해설/` 에서 자동 |
| 3부 연습문제 | 새로 만든 문제 → 끝에 **해설 모음** | Claude가 `3_연습문제.json` 작성 |

글씨체: 본문·해설 = KoPubWorld 바탕(이 스킬의 `fonts/`), 제목·문항 = Apple SD 산돌고딕 Neo(저장소 `fonts/`,
문제지와 같음). 사용자가 글씨체를 첨부하지 않아도 된다 — 아래 0단계가 설치한다.

## 0. 준비 (세션마다 한 번)
```bash
bash tools/setup.sh                                          # 패키지, wkhtmltopdf, 문항 글씨체(GichulTT)
python3 .claude/skills/pilgi-study/scripts/setup_fonts.py    # 본문 글씨체(StudyBatang) — 처음 40초쯤
```
`check_private.py` 가 `[OK]` 가 아니면 PDF는 만들어 보내되 **커밋·푸시는 하지 않는다**(기출이 들어 있다).

## 1. 수업 정하기
```bash
S=.claude/skills/pilgi-study/scripts/study.py
python3 $S find <과목> [검색어]        # 예: find 치료의기본 기도 → "32 응급기도관리 기출 13문항"
```
과목 = `과목정보/<과목>.json` 이름(띄어쓰기 없이: 진단의기본, 치료의기본, 인체감염학 …). 필기본 파일 이름·제목·
내용으로 과목과 수업을 추정하고, 후보가 둘 이상이면 사용자에게 묻는다. 과목정보에 없는 과목이면 새 과목 추가
(gichul-classify 스킬의 "New subject")가 먼저 필요하다고 알린다.

## 2. 자료 모으기
- **필기본**: 대화에 첨부한 파일, 또는 사용자가 `학습자료/<과목>/<id>_<수업명>/필기본/` 에 올린 파일.
  첨부로 받았으면 그 폴더에 `필기본_<연도>.<확장자>` 로 복사해 둔다(다시 만들 때 쓴다).
  - 연도는 사용자가 말한 것 → 파일 이름 → 내용 순. "올해" = 현재 연도, "작년" = 그 전 해.
  - PDF는 텍스트를 뽑고, 손글씨·도식·표가 있는 쪽은 페이지를 이미지로 보고 읽는다(그림 속 글자 놓치지 말 것).
    md/docx/이미지도 같은 방식. 끝까지 다 읽는다 — 1부는 "모든 내용"이 기준이다.
- **기출**: 자동.
  ```bash
  python3 $S gichul <과목> <수업>       # 그 수업 기출 전체: 문항·보기·정답·해설을 글로
  ```
  다 읽는다(그림은 `[그림: 경로]` 를 열어 본다). 1부에 기출 포인트를 넣고, 3부가 기출을 베끼지 않게 하는 데 쓴다.
  끝에 `!! 해설이 비어 있는 기출` 이 나오면 그 JSON의 `"explanation"` 을 gichul-classify 3b 규칙대로 채운다
  (같은 파일이 `해설지/` 에도 쓰인다). 기출이 0문항이면 2부는 "분류된 기출 없음"으로 나온다 — 사용자에게
  알리고, 기출 PDF가 있으면 `올리기/<과목>/` 에 올려 gichul-classify 로 먼저 분류하자고 제안한다.
  - 원본 시험이 저장소에 없고 필기본 등에 문항만 실려 있으면, 사용자가 원할 때 그 수업 폴더의
    `2_추가기출.json`(형식은 18_흡입마취 예시 참고: exam + questions[n, author, stem, choices, answer, explanation])
    에 문장·보기를 그대로 옮겨 적는다. 2부에 연도순으로 섞여 "필기본 수록"으로 표시된다. 원본이 분류되면 그 파일은 지운다.

## 3. 1부 쓰기 — `학습자료/<과목>/<id>_<수업명>/1_설명.md`
맨 첫 줄: `<!-- 필기본: 2026 -->` (작년 것도 썼으면 `<!-- 필기본: 2026 · 2025 -->`) — 표지·부 제목에 표시된다.

내용 원칙
- **올해 필기본의 모든 항목을 빠짐없이, 필기 순서대로.** 나열이 아니라 설명: 무엇인지 → 왜/기전 → 임상에서
  어떻게 쓰이는지 → 헷갈리는 것과의 차이. 필기의 약어·영어 용어는 처음 나올 때 풀어 쓰고 원어를 괄호로 둔다.
- 필기에 없는 교과서 지식은 이해를 돕는 정도로만 덧붙이고 필기와 어긋나게 쓰지 않는다. 필기가 틀려 보이면
  고치지 말고 `※ 확인 필요:` 로 적는다.
- **작년 필기본**이 있으면: 올해 것이 기준. 작년에만 있는 내용은 해당 위치에 `!!! diff "작년 필기와 다른 점"` 으로
  넣고(기출은 작년 강의에서 나왔을 수 있으니 버리지 않는다), 수치·분류·기준이 바뀐 곳도 같은 상자로 표시한다.
- **기출 연결**: 기출이 물은 내용이 나오는 자리에 `!!! exam "기출 포인트"` — 몇 번(2부 번호)이 무엇을 물었고 어떤
  오답 보기가 함정이었는지 한두 줄. 기출에 나왔는데 필기에 없는 내용도 짧게 설명해 넣는다.
- 비교는 표로, 꼭 외울 것은 `!!! memo "암기"`, 단원 요점은 `!!! key "핵심"`. 상자를 남발하지 않는다(단원당 1–3개).

형식 (Python-Markdown: tables, admonition, sane_lists)
```markdown
# 1. 대단원                  ← 파란 띠 제목
## 소단원
### 항목
본문 문단, - 목록, 1. 번호 목록, | 표 |, **굵게**, *강조(파란 굵은 글씨)*
!!! key "핵심"              ← 종류: key / exam / diff / memo, 내용은 4칸 들여쓰기
    내용
```

## 4. 3부 쓰기 — `학습자료/<과목>/<id>_<수업명>/3_연습문제.json`
```json
[
  {"stem": "문제 (사례형이면 사례까지)",
   "box": ["ㄱ. …", "ㄴ. …", "ㄷ. …"],         // 선택: <보기> 목록. 문자열 하나면 사례·자료 상자
   "choices": ["…", "…", "…", "…", "…"],        // 5지선다. 없으면 단답형(answer 에 정답 글)
   "answer": [3],                                // 정답 번호(1부터). 복수정답이면 [2, 4]
   "explanation": "왜 정답인지 + 주요 오답이 왜 틀렸는지 (2–5문장, 줄바꿈 \n 가능)",
   "point": "관련 개념 (1부 소단원 이름)"}
]
```
- 문항 수: 필기 분량에 맞춰 보통 10–15개(짧은 수업은 8개 이상). 사용자가 정하면 그 수.
- 이 학교 기출 문체를 따른다: "가장 적합한/옳은 것을 고르시오", 사례형, ㄱㄴㄷ 보기형을 섞는다.
- 1부 전체를 고르게 다루되 기출에 안 나온 고빈도 내용과, 기출에서 반복된 함정을 다른 각도로 묻는 문제를 우선.
  기출 문항을 그대로 또는 보기 순서만 바꿔 내지 않는다.
- 오답 보기는 그럴듯하게(수치 바꾸기, 비슷한 개념 바꿔치기, 기출의 함정). 정답 번호가 한쪽에 몰리지 않게.
- 정답은 필기본(과 기출 해설)에 근거해야 한다. 근거가 애매한 문제는 만들지 않는다.
- 문장 안에 `<b>`, `<sub>`, `<sup>` 는 그대로 쓸 수 있다.

## 5. 만들기·확인
```bash
python3 $S build <과목> <수업>
```
`[OK]` 세 줄(글씨체, 문항 번호, 정답·해설 항목 수)이 나와야 한다. FAIL이면 고치고 다시. 그다음 반드시
`work/_study/<과목>/<id>/pv/NN.png` 를 열어 본다: 표지, 1부 첫 쪽과 표가 있는 쪽, 2부 첫 쪽(연도 제목·출제자 줄),
그림 있는 기출, 2부 정답·해설 첫 쪽, 3부 문제·해설. 표가 쪽 밖으로 넘치거나 상자가 어색하게 잘리면 md를 손본다
(긴 표는 둘로 나누기).

## 6. 저장·전달
```bash
python3 tools/check_private.py && git add 학습자료/<과목> 해설 && git commit -m "<과목>: <id> <수업명> 학습자료"
git push        # main 에 못 올리면 브랜치를 올리고 PR — 사용자에게 초록 Merge 버튼 안내
```
`work/` 는 커밋하지 않는다. PDF는 SendUserFile 로 바로 보낸다(사용자는 대화에서 받아 본다).

보고(짧게): 파일 하나 + "1부 n개 단원 · 기출 n문항(연도) · 연습문제 n문항", 작년 필기와 달라진 핵심이 있으면
한 줄, `※ 확인 필요` 로 남긴 것이 있으면 목록.

## 고쳐 달라고 할 때
- "설명 더 자세히 / 이 부분 빼줘 / 연습문제 더" → `1_설명.md`·`3_연습문제.json` 만 고치고 5–6단계.
- "기출 n번 해설 틀렸어" → 2부 n번의 출처(시험·원번호)를 찾아 `해설/<과목>/<시험id>.json` 을 고친다(같은 문제가
  다른 해에도 있으면 함께). 해설지도 같은 JSON을 쓰므로 gichul-classify 규칙대로 `build_answers.py <과목> --only <id>`.
- "기출 n번은 이 수업 아니야" → gichul-classify 의 `classify.py set` 으로 옮기고 이 PDF와 문제지·해설지 다시 만들기.
