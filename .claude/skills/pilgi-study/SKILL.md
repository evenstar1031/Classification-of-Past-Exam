# 필기본 → 수업별 학습자료 (3부 구성)

사용자는 이 PDF 하나로 시험공부를 한다. 코딩은 하지 않으니 결과 위주로 짧게 한국어로 보고한다.

| 부 | 내용 | 출처 |
|---|---|---|
| 표지 | 과목 · 강 번호 · 수업명 · 목차 | 자동 |
| 1부 개념 설명 | 필기본의 **모든** 내용을 설명 + 공부해야 할 **표·도식·사진은 필기본에서 잘라 넣기** | Claude가 `1_설명.md` 작성, 그림은 `fig` |
| 2부 기출문제 | 그 수업으로 분류된 기출 전부, 최신 연도부터, `문제지/`와 같은 양식 → 끝에 **정답·해설 모음** | `_자동관리/분류/` + `_자동관리/해설/` 에서 자동 |
| 3부 연습문제 | 새로 만든 문제 → 끝에 **정답표**(번호·정답만) → **해설 모음** | Claude가 `3_연습문제.json` 작성 |

> **과목 폴더 이름** — 보이는 폴더(`문제지/`·`해설지/`·`학습자료/`·`올리기/`·`자료실/`)의 과목 폴더는 `2학기/01. 진단의 기본` 처럼 「학기/순서 번호. 과목 이름」이고,
> `_자동관리/` 안(분류·해설·작업기록·원본·과목정보)과 프로그램 인자는 과목 키(`진단의기본`)다. 아래 `<과목>` 은 그 위치에 맞게 읽는다.
> 대응표: `python3 _자동관리/tools/subjects.py`. 프로그램에는 키·폴더 이름 어느 쪽을 넣어도 된다. 새 과목은 `subjects.py` 의 그 학기 목록 끝에 더한다.

## 두 단계 (수업 전 → 수업 후)
사용자는 한 수업의 학습자료를 두 번에 나눠 받는다. 요청(이슈 「단계」 칸, 앱에서 고른 단계, 대화 문장)으로 정한다.
말이 없으면: 올해 필기본(`필기본_<올해>`)이 있으면 **수업 후**, 작년 것만 있으면 **수업 전**.

| 단계 | 언제 | 쓰는 필기 | 만드는 것 |
|---|---|---|---|
| **수업 전** | 강의 전 예습 | 작년 필기본(`필기본_<작년>`) | 1부(작년 필기 전체 설명 + 기출 포인트) + 2부 기출. **3부 없음** |
| **수업 후** | 강의 후 | 올해 필기본(`필기본_<올해>`) + 작년 것 | 수업 전 1부를 올해 필기로 **보충·수정** + 2부 기출 + **3부 연습문제** |

- 수업 전: `1_설명.md` 첫 줄 `<!-- 필기본: 2025 -->`, 둘째 줄 `<!-- 단계: 수업 전 -->`. `3_연습문제.json` 은 만들지
  않는다(있어도 build 가 넣지 않는다). 작년 필기가 기준이므로 "올해 강의에서 바뀔 수 있음"을 따로 적을 필요는 없다.
- 수업 후: 이미 있는 `1_설명.md`(수업 전판)를 **지우고 새로 쓰지 말고 고쳐 쓴다.** 올해 필기를 처음부터 끝까지 읽고
  1) 올해 필기 순서로 단원을 맞추고, 2) 올해 새로 생긴 내용은 그 자리에 `!!! new "올해 필기에서 추가"` 상자 또는 본문으로
  넣고, 3) 수치·기준·분류가 바뀐 곳은 올해 것으로 고친 뒤 `!!! diff "작년 필기와 다른 점"` 으로 작년 값을 남기고,
  4) 올해 빠진 작년 내용은 지우지 말고 `diff` 상자로 둔다(기출은 작년 강의에서 나왔다). 첫 줄을
  `<!-- 필기본: 2026 · 2025 -->`, 둘째 줄을 `<!-- 단계: 수업 후 -->` 로 바꾸고 4단계대로 3부를 만든다.
  수업 전판이 없으면(바로 수업 후로 온 경우) 아래 3단계 규칙 그대로 처음부터 쓴다.
- 파일 이름은 두 단계 모두 `<id>_<수업명>_학습자료.pdf` — 수업 후판이 수업 전판을 덮어쓴다. 앱은 `단계` 줄을 읽어
  "수업 전판"인지 보여 준다.
- 보고에 단계를 적는다: "수업 전판 · 1부 n단원 · 기출 n문항" / "수업 후판 · 올해 추가 n곳 · 바뀐 곳 n곳 · 연습문제 n문항".

글씨체: 본문·해설 = KoPubWorld 바탕(이 스킬의 `fonts/`), 제목·문항 = Apple SD 산돌고딕 Neo(저장소 `_자동관리/fonts/`,
문제지와 같음). 사용자가 글씨체를 첨부하지 않아도 된다 — 아래 0단계가 설치한다.

## 0. 준비 (세션마다 한 번)
```bash
bash _자동관리/tools/setup.sh                                          # 패키지, wkhtmltopdf, 문항 글씨체(GichulTT)
python3 .claude/skills/pilgi-study/scripts/setup_fonts.py    # 본문 글씨체(StudyBatang) — 처음 40초쯤
```
`check_private.py` 가 `[OK]` 가 아니면 PDF는 만들어 보내되 **커밋·푸시는 하지 않는다**(기출이 들어 있다).

## 1. 수업 정하기
```bash
S=.claude/skills/pilgi-study/scripts/study.py
python3 $S find <과목> [검색어]        # 예: find 치료의기본 기도 → "32 응급기도관리 기출 13문항"
```
과목 = `_자동관리/과목정보/<과목>.json` 이름(띄어쓰기 없이: 진단의기본, 치료의기본, 인체감염학 …). 필기본 파일 이름·제목·
내용으로 과목과 수업을 추정하고, 후보가 둘 이상이면 사용자에게 묻는다. 과목정보에 없는 과목이면 새 과목 추가
(gichul-classify 스킬의 "New subject")가 먼저 필요하다고 알린다.

## 2. 자료 모으기
- **필기본**: 대화에 첨부한 파일, 또는 사용자가 `학습자료/<과목>/<id>_<수업명>/필기본/` 에 올린 파일.
  첨부로 받았으면 그 폴더에 `필기본_<연도>.<확장자>` 로 복사해 둔다(다시 만들 때 쓴다).
  - 연도는 사용자가 말한 것 → 파일 이름 → 내용 순. "올해" = 현재 연도, "작년" = 그 전 해.
  - PDF는 텍스트를 뽑고, 손글씨·도식·표가 있는 쪽은 페이지를 이미지로 보고 읽는다(그림 속 글자 놓치지 말 것).
    md/docx/이미지도 같은 방식. 끝까지 다 읽는다 — 1부는 "모든 내용"이 기준이다.
- **기출**: 자동.
  ```bash
  python3 $S gichul <과목> <수업>       # 그 수업 기출 전체: 문항·보기·정답·해설을 글로
  ```
  다 읽는다(그림은 `[그림: 경로]` 를 열어 본다). 1부에 기출 포인트를 넣고, 3부가 기출을 베끼지 않게 하는 데 쓴다.
  끝에 `!! 해설이 비어 있는 기출` 이 나오면 그 JSON의 `"explanation"` 을 gichul-classify 3b 규칙대로 채운다
  (같은 파일이 `해설지/` 에도 쓰인다). 기출이 0문항이면 2부는 "분류된 기출 없음"으로 나온다 — 사용자에게
  알리고, 기출 PDF가 있으면 `올리기/<과목>/` 에 올려 gichul-classify 로 먼저 분류하자고 제안한다.
  - 원본 시험이 저장소에 없고 필기본 등에 문항만 실려 있으면, 사용자가 원할 때 그 수업 폴더의
    `2_추가기출.json`(형식은 18_흡입마취 예시 참고: exam + questions[n, author, stem, choices, answer, explanation])
    에 문장·보기를 그대로 옮겨 적는다. 2부에 연도순으로 섞여 "필기본 수록"으로 표시된다. 원본이 분류되면 그 파일은 지운다.

## 3. 1부 쓰기 — `학습자료/<과목>/<id>_<수업명>/1_설명.md`
맨 첫 줄: `<!-- 필기본: 2026 -->` (작년 것도 썼으면 `<!-- 필기본: 2026 · 2025 -->`) — 표지·부 제목에 표시된다.

내용 원칙
- **올해 필기본의 모든 항목을 빠짐없이, 필기 순서대로.** 나열이 아니라 설명: 무엇인지 → 왜/기전 → 임상에서
  어떻게 쓰이는지 → 헷갈리는 것과의 차이. 필기의 약어·영어 용어는 처음 나올 때 풀어 쓰고 원어를 괄호로 둔다.
- 필기에 없는 교과서 지식은 이해를 돕는 정도로만 덧붙이고 필기와 어긋나게 쓰지 않는다. 필기가 틀려 보이면
  고치지 말고 `※ 확인 필요:` 로 적는다.
- **작년 필기본**이 있으면: 올해 것이 기준. 작년에만 있는 내용은 해당 위치에 `!!! diff "작년 필기와 다른 점"` 으로
  넣고(기출은 작년 강의에서 나왔을 수 있으니 버리지 않는다), 수치·분류·기준이 바뀐 곳도 같은 상자로 표시한다.
- **기출 연결**: 기출이 물은 내용이 나오는 자리에 `!!! exam "기출 포인트"` — 몇 번(2부 번호)이 무엇을 물었고 어떤
  오답 보기가 함정이었는지 한두 줄. 기출에 나왔는데 필기에 없는 내용도 짧게 설명해 넣는다.
- 비교는 표로, 꼭 외울 것은 `!!! memo "암기"`, 단원 요점은 `!!! key "핵심"`, 수업 후판에서 올해 새로 생긴 내용은 `!!! new "올해 필기에서 추가"`. 상자를 남발하지 않는다(단원당 1–3개).

### 필기본의 표·그림 넣기 (기본으로 한다)
필기본 슬라이드 중 **공부해야 하는 표·도식·그래프·사진**(분류표, 비교표, 기전 도식, 경로 그림, 약물 표, 흐름도,
척도표 등)은 다시 그리거나 글로만 옮기지 말고 **필기본에서 잘라 그 자리에 넣는다.** 손글씨·형광펜 메모도 같이 보인다.
제목·글자만 있는 슬라이드, 표지, 장식 사진은 넣지 않는다. 그림 아래에는 핵심을 글(필요하면 md 표)로 다시 정리해
그림 없이도 읽히게 한다.
```bash
python3 $S fig <과목> <수업> <쪽> <이름>                       # 필기본 PDF 한 쪽 통째로 → 그림/<이름>.png
python3 $S fig <과목> <수업> <쪽> <이름> --box 0 0.15 1 0.9   # 일부만 (쪽 크기 대비 x0 y0 x1 y1, 0~1)
```
이름은 `f<쪽>_<내용>` (예: `f45_APAP대사`). 필기본 PDF가 여러 개면 `--pdf 경로`. md에는
`![캡션](그림/f45_APAP대사.png){: style="width:72%"}` — 캡션이 그림 아래 회색 줄로 나오고, 폭은 슬라이드 하나가
쪽의 반쯤 차지하도록 보통 65–80%. 그림이 없으면 build 가 멈춘다. 제목은 build 가 다음 덩어리와 묶어 쪽 끝에 홀로
남지 않게 한다.

형식 (Python-Markdown: tables, admonition, sane_lists, attr_list)
```markdown
# 1. 대단원                  ← 파란 띠 제목
## 소단원
### 항목
본문 문단, - 목록, 1. 번호 목록, | 표 |, **굵게**, *강조(파란 굵은 글씨)*
!!! key "핵심"              ← 종류: key / exam / diff / memo / new, 내용은 4칸 들여쓰기
    내용
```

## 4. 3부 쓰기 — `학습자료/<과목>/<id>_<수업명>/3_연습문제.json`
```json
[
  {"stem": "문제 (사례형이면 사례까지)",
   "box": ["ㄱ. …", "ㄴ. …", "ㄷ. …"],         // 선택: <보기> 목록. 문자열 하나면 사례·자료 상자
   "choices": ["…", "…", "…", "…", "…"],        // 5지선다. 없으면 단답형(answer 에 정답 글)
   "answer": [3],                                // 정답 번호(1부터). 복수정답이면 [2, 4]
   "explanation": "왜 정답인지 + 주요 오답이 왜 틀렸는지 (2–5문장, 줄바꿈 \n 가능)",
   "point": "관련 개념 (1부 소단원 이름)"}
]
```
- 문항 수: 필기 분량에 맞춰 보통 10–15개(짧은 수업은 8개 이상). 사용자가 정하면 그 수.
- 이 학교 기출 문체를 따른다: "가장 적합한/옳은 것을 고르시오", 사례형, ㄱㄴㄷ 보기형을 섞는다.
- 1부 전체를 고르게 다루되 기출에 안 나온 고빈도 내용과, 기출에서 반복된 함정을 다른 각도로 묻는 문제를 우선.
  기출 문항을 그대로 또는 보기 순서만 바꿔 내지 않는다.
- 오답 보기는 그럴듯하게(수치 바꾸기, 비슷한 개념 바꿔치기, 기출의 함정). 정답 번호가 한쪽에 몰리지 않게.
- 정답은 필기본(과 기출 해설)에 근거해야 한다. 근거가 애매한 문제는 만들지 않는다.
- 문장 안에 `<b>`, `<sub>`, `<sup>` 는 그대로 쓸 수 있다. 위첨자 ⁺ 기호는 글씨체에 없으니 `Ca<sup>2+</sup>` 로 쓴다(1부 md도 같음).
- **정답표는 자동**: 3부 "연습문제 정답·해설" 맨 앞에 번호·정답만 모은 표(한 줄 10문항)가 먼저 나오고, 그 뒤에
  문항별 해설이 이어진다. JSON에 따로 쓸 것은 없다.

## 5. 만들기·확인
```bash
python3 $S build <과목> <수업>
```
`[OK]` 세 줄(글씨체, 문항 번호, 정답·해설 항목 수)이 나와야 한다(수업 전판은 연습 0). FAIL이면 고치고 다시. 그다음 반드시
`work/_study/<과목>/<id>/pv/NN.png` 를 열어 본다: 표지, 1부 첫 쪽과 표가 있는 쪽, 2부 첫 쪽(연도 제목·출제자 줄),
그림 있는 기출, 2부 정답·해설 첫 쪽, 3부 문제, **3부 정답표**와 해설. 1부에 넣은 필기본 그림이 잘리지 않고 글씨가
읽히는지, 제목만 쪽 끝에 남은 곳이 없는지도 본다. 표가 쪽 밖으로 넘치거나 상자가 어색하게 잘리면 md를 손본다
(긴 표는 둘로 나누기).

## 6. 저장·전달
```bash
python3 _자동관리/tools/check_private.py && git add 학습자료/<과목> _자동관리/해설 && git commit -m "<과목>: <id> <수업명> 학습자료"
git push        # main 에 못 올리면 브랜치를 올리고 PR — 사용자에게 초록 Merge 버튼 안내
```
`work/` 는 커밋하지 않는다. PDF는 SendUserFile 로 바로 보낸다(사용자는 대화에서 받아 본다).

보고(짧게): 파일 하나 + "1부 n개 단원 · 기출 n문항(연도) · 연습문제 n문항", 작년 필기와 달라진 핵심이 있으면
한 줄, `※ 확인 필요` 로 남긴 것이 있으면 목록.

## 고쳐 달라고 할 때
- "설명 더 자세히 / 이 부분 빼줘 / 연습문제 더" → `1_설명.md`·`3_연습문제.json` 만 고치고 5–6단계.
- "기출 n번 해설 틀렸어" → 2부 n번의 출처(시험·원번호)를 찾아 `_자동관리/해설/<과목>/<시험id>.json` 을 고친다(같은 문제가
  다른 해에도 있으면 함께). 해설지도 같은 JSON을 쓰므로 gichul-classify 규칙대로 `build_answers.py <과목> --only <id>`.
- "기출 n번은 이 수업 아니야" → gichul-classify 의 `classify.py set` 으로 옮기고 이 PDF와 문제지·해설지 다시 만들기.
